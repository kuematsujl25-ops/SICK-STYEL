# 統一依頼窓口（開発版）

入力窓口を一つにまとめ、ルール版1で主担当と協力担当を分類します。キーワードの種類数を比較し、同点・該当なしは未分類／確認待ち。分類はモデルを使いません。確認画面で担当を変更でき、履歴を監査ログに記録します。協力担当は別ジョブを作らないため実行数を増やしません。

受付は既存AI社員ドキュメントのjobsに保存します。自発的分析の依頼、従来依頼、今回の受付を同じ一覧で追跡し、成果物・レビュー履歴への導線を維持します。入力の重複は受付フィンガープリントとrevisionで防止します。

## 送信と状態の制約

自由入力の外部送信は未承認のため、分類後も送信承認待ちです。この変更には承認解除APIを設けません。既存ランナーが取得するqueuedには入りません。taskPacketとimportも拒否します。名前・団体名を自動匿名化したと保証せず、本文はアプリ内だけに保持します。秘密値やメールは入力検査で拒否します。

ランナーは既存管理者セッションでCAS claimを取得し、同時実行2件まで。30秒ごとのheartbeat、開始日時、失敗理由（定型コード）、試行回数を保存します。90秒以上更新がなければ通信途絶・未確認表示。10分のleaseが切れても自動再実行せず、本人が再実行を予約します。試行上限は永続2回です。停止／通信断で子プロセスを終了し、失効したclaimによる成果物は保存しません。通信断で失敗を保存できない場合も最新状態と見せません。

起動するMacランナーは匿名の期限超過担当タスク集計だけを対象にし、定型指示・件数・日時・ハッシュの形式を送信直前に検証します。他種別や自由入力は送信しません。旧ランナーの更新・再ログインが必要です。認証情報の永続保存は追加しません。

ローカルSQLiteとダミー入力で分類→保存→再読込、担当確定、監査・重複・外部送信拒否、停止・失敗・通信断・claim競合を検証します。
