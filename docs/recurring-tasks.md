# 毎朝8時の継続タスク

通常の「タスク」と「担当タスク」の追加画面で、単発／継続（毎日8時）を選びます。継続の場合、期限欄は開始日になります。開始日以降、毎朝08:00 Asia/Tokyoに当日期限の新しい未完了タスクを作ります。今日の8時以降に登録した場合は次の確認（通常15分以内）で当日分を作ります。担当・優先度・メモ・関連先も引き継ぎます。

各画面の「継続タスク設定」から内容を編集し、停止／再開できます。編集は次回生成分から反映されます。停止していた日は再開時に埋めず、今日以降を再開します。開始日と出力先は変更不可です。変更したい場合は旧設定を停止し、新しい設定を追加してください。過去の完了・未完了・ゴミ箱はそのまま残ります。

開いているタスク／担当タスク／ダッシュボードは既存の1分ごとの取得とフォーカス復帰時に最新状態を反映します。編集中のダイアログや入力欄を上書きしません。更新が競合した場合は再読み込みが必要です。

## 保存と再実行

既存workspace文書にrecurringTasks配列を追加し、旧データでは空配列に補完します。DBスキーマ変更はありません。生成タスクにはrecurringIdとoccurrenceDateを保存し、テンプレートのnextDateと同じrevision条件付きUPDATEでまとめて確定します。競合時は最新データを読み直し、最大4回試行します。失敗してもカーソルだけが進むことはありません。生成済みタスクの削除・完了変更後も同じ日を再生成しません。

日付計算は端末のタイムゾーンに依存しません。朝8時を過ぎた日まで処理し、障害後は1テンプレートにつき1実行最大31日分を補完します。長い停止からの復旧は次回実行で続きます。停止テンプレートは対象外です。既存の配列上限10,000件に達するとバッチ全体を保存せず失敗します。履歴を自動削除する処理はありません。運用でバックアップ・容量管理を行ってください。

旧クライアントや古いバックアップがテンプレートを消したり生成カーソルを巻き戻したりする更新は拒否します。継続設定導入前のバックアップ復元には管理者による内容の照合が必要です。最新バックアップは通常どおり利用できます。
