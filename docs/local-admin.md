# ローカルの管理者作成

`SETUP_TOKEN`が初期設定キーの環境変数名です。ログイン用パスワードとは別の、初回登録を管理者に制限する秘密値です。

以前は`.env.bootstrap`にキーを生成しただけでNodeサーバーに読み込んでおらず、さらに検証用3002ポートは別のテストキーで起動していました。現在は検証サーバーを停止し、通常の3000ポートで修正版を起動しています。

## キーを表示しない推奨手順

このリポジトリで次を実行します。

```sh
npm run setup:local
npm run admin:create
npm start
```

`admin:create`はメールアドレスとパスワードを本人の対話ターミナルで聞きます。パスワードは表示されません。管理者が既に存在する場合は変更せず停止します。作成後、http://127.0.0.1:3000 を再読み込みし、メールアドレスとパスワードでログインしてください。すでにサーバーが動いていれば`npm start`の重複実行は不要です。

キーを回答・ログ・コマンド引数へ出す必要はありません。パスワードをチャットに送らないでください。

## 読み込みの優先順位

1. サーバー起動時のシェル環境変数（`SETUP_TOKEN`など）
2. `.env.local`（通常のKEY=VALUE形式）
3. `.env`（通常のKEY=VALUE形式）
4. `.env.bootstrap`（秘密値のJSON。Git除外・権限600）

`.env.local`は`.env`より優先します。既にシェルに設定された値はファイルで上書きしません。ダウンロードされた`[SENSITIVE]`のプレースホルダーは実キーとして使いません。サーバーは起動時に読み込むため、設定変更後は再起動が必要です。

`npm start`のログには「管理者初期設定: 利用可能（秘密値は非表示）」だけを出します。キー自体は出しません。`/api/session`も設定の有無だけを返します。

Node本番や隔離テスト（DATA_DIR指定）ではローカル秘密ファイルを自動読込しません。WorkersはCloudflareのSecretsから読み込みます。Wranglerのローカル検証には`setup:local`で生成する`.dev.vars`を使います。実行環境と保存先を混ぜないでください。

## ブラウザーで登録する場合

初期設定キー欄へ、サーバーが読み込んだ`SETUP_TOKEN`と同じ値を本人の非公開設定から入力してください。パスワードマネージャーがログインパスワードを誤入力した場合は一致しません。キー未設定・キー未入力・不一致は、値を示さず別々のエラーを表示します。
