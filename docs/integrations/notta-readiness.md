# Notta Premium 接続準備（2026-10-28）

## 方針

Premiumのまま進める。Business/Zapier、有料オプションへの変更は対象外。マージ、本番デプロイ、OAuth許諾、永続アクセス設定、会議参加・録音開始は別承認が必要。設定の存在だけで接続済みにしない。

## アカウント画面で確認した状態

- Notta Premium。Google Calendar接続済み、Zoom未接続。
- Notta Botの「カレンダー予定への自動参加」「Zoomミーティングへの自動参加」「自動メール共有」は全てオフ。
- 録音通知バナー、ホスト承認必須、録画開始メッセージ通知はオン。Web会議の録画はオフ。すべて変更していない。
- Zoomの許諾画面まで開いたがAllowは押していない。表示されたZoomアカウントはNottaアカウントのメールアドレスと異なるため、利用者による対象アカウント照合が必要。個人メールアドレス・ワークスペースID・認証URLは公開リポジトリに記録しない。

Zoom許諾画面のアプリ名は **AI Notetaker by Notta**。閲覧カテゴリはプロフィール/連絡先、カレンダー、アカウント情報、設定、利用状況、登録情報、参加者情報、コンテンツ、機能。管理カテゴリは登録/スケジュール作成、参加者、コンテンツ。未使用時にも情報にアクセス・管理できる旨が表示される。「共有アクセス権限を使う」は未選択のまま。これは画面上のカテゴリであり、内部OAuthスコープ文字列の確認を意味しない。

Zoom連携はPremiumの範囲で利用できる。公式案内では接続後にNotta側の自動参加設定をオンにすると、自分が主催するZoom会議への参加を試みる。SICK STYLEだけに限定する機能とは限らないため、アカウント全体の自動参加は有効化しない。対象会議ごとの告知・同意・ホスト承認が必要。

## 現契約で実装・検証した取り込み

1. Nottaで対象ノートを開き「ダウンロード」→TXT。本文用は文字起こしを含め、AI要約を除外する。元の発言を保つため改行を残す。
2. AI要約は別途コピーするか、文字起こしを含めずAI要約のみのTXTを出力する。既存要約の読み取りだけで、新たな生成や有料処理を開始しない。
3. アプリの対象団体・会議枠で本文TXTと要約TXTをそれぞれ読み込む。UTF-8、最大60KB、本文20,000文字、要約5,000文字。ファイル読み込みはブラウザ内のみ。入力済みの内容は上書きしない。
4. Nottaのノート画面URL、会議日時、内容、告知・同意・保存権限を利用者が確認して保存する。本文とAI要約を自動分類しない。音声/動画、他業務のノートは転送しない。
5. 数値は全て確認待ち候補として保存し、根拠確認後の操作で反映する。既存値・履歴・重複防止・取消・更新競合保護を維持する。

Notta側の自動参加とアプリ側の自動同期は別機能。今回の取り込みは手動であり、アプリの「Notta自動連携：未接続」表示を維持する。長い本文は切り捨てず拒否する。元ノートを保全し、必要範囲を利用者が確認して入力する。

## Premiumで検討できる他の取得経路

### 公式Notta CLI / MCP

公式ヘルプで新たに確認した経路。`@notta-labs/notta-cli` 1.0.9 の公開配布ソースを一時ディレクトリで調査した（グローバルインストール・認証・MCP登録は未実施）。既存CLIコマンドと既定認証ファイルは見つからなかった。

- `notta record view RECORD_ID`：完成した文字起こしの取得。
- `notta summary batch RECORD_ID`：既存要約の取得。生成操作ではない。
- 上記の配布実装が要求する権限は `resource.record.read`。
- OAuth/PKCEにより選択したNottaワークスペースへ接続。既定の資格情報保存先は `~/.config/notta_cli/credentials.json`、ファイルモード0600。access/refresh tokenが永続保存されるため、認証完了前に承認が必要。
- 権限は認証画面で選択する方式。CLIは削除・アップロード等も備えるため、標準設定が読み取り専用だとは扱わない。録音・アップロード・要約生成・削除・共有権限は要求しない。
- 公式セットアップ資料にはBusiness必須の記載はないが、Premiumでの対象アカウントの利用資格と追加料金なしの実行は未検証。無料と断定しない。実際の許諾画面と制限を確認してから接続する。
- アプリへの自動同期は未実装。承認後は指定したSICK STYLEレコードだけ取得し、本文/要約の確認・同意・対象会議への対応確認を経て保存する。全ノートを一括取得しない。認証情報はブラウザや公開リポジトリに入れない。

### Google Drive等への手動出力

公式ヘルプ上はPremium対応。Nottaの「外部サービスに同期」→「クラウドに保存する」で、形式・保存先を選んで同期する方式。現在Google Driveは未接続。新規OAuthと外部への議事録転送が必要なので実施しない。Google Calendarの既存認可をDrive用に流用しない。TXT直接取り込みで目的を満たせる間は追加権限不要。

## 正確な残作業

- 利用者がNottaとZoomの対象アカウントを照合。その後必要ならZoom許諾画面の上記権限に対して明示承認（現時点は未許可）。資格情報はNotta側が管理し、SICK STYLEには保存しない。
- 自動参加はオフのまま、対象会議を選ぶ運用を決める。実会議のボット招待・録音は未実施。
- 公式CLI方式を採用する場合、料金/利用資格・権限の実画面確認→新規永続アクセスの承認→最小権限接続→指定ダミーノート取得検証→アプリ受け渡し実装の順。承認前にcredentialを生成・保存しない。
- TXTファイル選択のブラウザE2Eは拡張機能のファイルURLアクセス無効により未完了。制限の迂回や権限変更はしない。読込・上限・文字コード・既存入力保全・本文/要約分離はダミー自動テストで確認する。
