# Notta 接続準備（2026-10-28）

## 現状と今回の範囲

Mac上の既存ログインで確認：Notta Premium、Google Calendar接続済み、Zoom未接続。ZapierはBusiness対象として表示される。Calendar接続済みだけでは、対象会議への自動参加が有効とは判断できない。会議への参加、録音、OAuth許諾、契約変更、実録音の転送は行っていない。

アプリ側にはNotta認証情報、APIアダプター、webhook受信口はない。UIの未接続表示を維持する。公開の直接API・webhook仕様と利用資格は未確認であり、非公開APIを推測して実装しない。

現契約のまま使う経路：Nottaで利用者が書き出したUTF-8 TXTを議事録フォームへ読み込む。ファイル読込はブラウザ内のみ、出典URL、対象団体/会議枠、会議日時、要約、告知・同意・保存権限を利用者が確認して保存する。本文60KB/20,000文字、要約5,000文字以内。音声・動画・DOCX/PDFは受け付けない。要約は別入力とし自動生成しない。元本文を変更せず根拠行を保持する。既存入力は上書きしない。

数値は全て確認待ち候補に保存し、明確な確定発言も即時反映しない。「根拠を確認して反映」で初めて更新する。曖昧な発言・複数根拠は推測せず、人が数値を確認する。過去の自動反映履歴は維持し、取消操作も維持する。

## 自動連携を有効化する前の判断

1. **会議参加**：既存Google Calendar連携の対象カレンダーと対象Zoom会議を利用者が確認。全予定への参加を有効化しない。対象をSICK STYLEの同意済み会議に絞る。Zoom連携が必要なら、Notta→Zoomの許諾画面で実際の要求権限を確認し、承認直前に提示する。現時点で具体的なOAuthスコープは未確認。
2. **同期方式と費用**：公式案内のZapier経由が候補。現プランの対象外なので、Nottaのプラン変更はこの作業では実施しない。必要プランとZapier側の費用・権限を利用者が確認し、採用を決定するまで本番受信口は追加しない。
3. **許諾と保存先**：採用する場合はNotta→Zapierの永続アクセス、Zapier→SICK STYLEの受信専用資格情報を別途承認する。NottaのOAuth情報はZapier接続管理、受信資格情報はZapier接続設定とCloudflare Workers Secretsへ保管する予定。まだ生成・保存していない。正確な権限はサービスの実際の許諾画面で確定する。
4. **データ範囲**：許可したSICK STYLE会議のNottaレコードID/出典URL、本文、要約、会議日時だけをZapierからアプリの非公開D1保存へ。音声/動画、他業務のノート、参加者一覧の転送は含めない。保持期間、削除・バックアップ方針は接続承認前に決める。

## 同期方式承認後に実装する受信処理

- 契約・実際のpayload仕様確認後に認証付き受信口を追加。管理者セッションや既存Zoom秘密値を受信認証に流用しない。
- レコードIDで冪等化、再送・本文改訂・容量上限・失敗時再試行・資格情報失効を検証する。
- 団体IDと会議枠への対応を明示的に保存。曖昧なタイトルや時刻だけで自動紐付けしない。
- 未対応レコードは隔離した確認待ちへ。同意をpayloadの固定値で代行せず、アプリ上の対象会議ごとの利用者確認が必要。
- 数値は今回と同じ確認待ち候補フローを使用する。
- 設定の存在、認証成功、ダミー同期成功、実会議への参加許可を別々の状態として表示する。設定だけで「接続済み」にしない。

## ローカル検証

`npm test` はWorkersの未アップロードビルドとNodeテスト。新規テストはダミーTXTのみ。UTF-8/サイズ/文字数/バイナリ拒否、入力保全、同意非代行、候補の承認・取消、重複と競合を確認する。本番データ・秘密値をテストに使用しない。
