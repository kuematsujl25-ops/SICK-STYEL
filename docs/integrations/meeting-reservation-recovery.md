# 中断された会議予約の安全な復旧

外部会議操作の前に保存した`creating`状態がWorker停止や継続的なDB書込失敗で残ると、旧実装ではすべての操作が拒否され、通常の管理画面では復旧できなかった。既存本番から存在する問題で、Nottaタグの変更が新たに生じさせたものではない。

会議画面の「中断した処理を確認（15分経過後）」は、保存済みIDのZoom会議とCalendar予定をGETで照合する。ZoomホストID、主催カレンダー、event IDも確認する。ID未保存、404/403、通信失敗、所有者不一致は未作成と断定せず、すべて要確認とする。タイトル検索による推測で別会議を紐付けない。参加URLや既存IDは変更しない。秘密値・ホスト専用start_url・プロバイダの応答全文は返さない。

復旧対象は最終予約更新から15分以上経過したcreatingだけ。15分経過は元処理の停止を証明しないため、確認画面で利用者が停止を確認するチェックを自分で入れる必要がある。復旧後は常に`uncertain`となり、自動再作成・自動同期・自動取消は行わない。既存の正常会議や進行中の新しい操作を回収しない。

利用者はZoom・Calendarの管理画面で、ID未保存を含む結果不明の会議・予定を確認・解決する。`uncertain`の「MTGを取消」も独立した確認画面で外部確認チェックが必須。記録済みIDだけを既存の取消手順で扱い、ID不明の外部リソースをアプリが発見・削除したと扱わない。対象アカウントや所有者記録が不明な旧データは確認停止し、DBを直接消して回避しない。

各予約に任意フィールド`operationId`を付け、復旧時は別IDへ切り替える。古い実行の保存・保存再試行はID不一致で拒否する。Zoom応答後にCalendar操作へ進む前と取消の各外部操作前にもIDを確認し、古い処理の後続書込を止める。既に送信済みの外部リクエストを取り消すことはできないため、外部の最終状態は利用者が確認する。新規ZoomのID保存時に復旧との競合を検出した場合は、代償削除を勝手に行わない。

既存データの破壊的移行・新しいOAuth scope・認証情報変更なし。GET権限が既存接続に無い場合も新しい許諾は要求せず要確認に止める。旧VersionにRollbackするとこの復旧UIとoperationIdチェックは利用できなくなるが、会議ID・URLは保全される。

ダミーテスト: 既存ID/所有者の照合、ID未保存・404・403・所有者不一致、15分以内拒否、確認未選択拒否、同時更新、遅延した旧作成応答、後続Calendar書込の停止、DB失敗と再試行。実会議の作成・更新・取消・録音を検証に使用しない。
