# Phase U: 団体営業・選手調査 — 実装範囲と次フェーズ（2026-10-21）

## 今回PRで実装する機能

- 団体営業の表示を「DM → ZOOM → サンプル → 試用 → 活用法提案ZOOM → 導入」の6段階に整理する。細かい予約・実施・到着確認・継続購入の既存ステータスと履歴は残す。
- 各団体に初回・活用法提案のMTG日時（JST）と参加URLを保持できるようにする。古いデータは項目がなくても有効。
- 日時保存後、Google Calendarの予定作成画面を開くリンクを提供する。**これはカレンダーへの自動登録ではない**。ブラウザーで本人が予定と参加者を確認して保存する。
- Jリーグ・海外のドリブラー8名を候補研究リストとして表示。出典・対象年度・数値の単位を記載し、候補として登録可。未接触/提供済みは分離する。
- 写真は権利確認済みのURLとクレジットを登録できる。出典に公式プロフィールがあればリンクで開く。未確認写真を勝手に複製・サイト掲載しない。ヤン・ディオマンデとラミン・ヤマルの調査カードに限り、Wikimedia CommonsのCC BY 4.0写真を作者・出典・ライセンスリンク付きで表示する。人物の肖像権や広告利用・推薦の許諾は別問題であり、SICKSTYLEとの関係を意味しない。

## 対応していないもの

- **ZOOM会議の自動生成、Googleカレンダーへの自動イベント登録、イベントの変更同期、相手への自動招待は未実装。**
- Google Calendar/ZoomがChatGPTのコネクタで利用できても、Cloudflare上で動くSICKSTYLEアプリの認証権限には継承されない。
- 写真ライセンスの自動取得・選手契約/提供実績の自動判定・サッカー有料統計の無許諾取り込みは未実装。
- 選手のフェイント数は統一定義のソースが確保できないため未取得。動画の基準（1対1時の上体/足のフェイク、同一動作の重複排除など）を決めて手動調査し、監査可能な根拠を添える。

## 次フェーズ：Zoom × Google Calendarの本物の自動同期

1. 管理者本人が Google OAuth と Zoom OAuth を別々に認可する。Googleは最小のカレンダー作成スコープ、Zoomは会議作成スコープのみ。Client ID/Secretの登録と同意画面設定を担当者の承認で行う。Zoomのプランと設定を先に確認。
2. コールバックはSICKSTYLEの既存認証・CSRF検証・state固定で検証し、短期認可コードからアクセストークン/リフレッシュトークンを取得。暗号化してサーバー側DBに保管、UIやJSONバックアップに含めない。
3. 団体ごとに「初回ZOOM」「活用法提案ZOOM」の種別・開始日時・終了日時・タイムゾーン・担当者・参加者を確定し、既存文書のrevisionを確認した後に会議作成リクエストを受け付ける。
4. 同一団体+種別+要求IDで冪等化。Zoom `POST /users/me/meetings` を実行して**参加者用join_urlのみ**取得し、Google Calendar events.insert で予定を作成。ホスト専用start_urlは外部共有しない。
5. Zoom成功・Calendar失敗は「部分成功」と記録し、重複する新しいZoom会議を発行せず同じ会議で再試行する。両方成功して初めて「連携済み」。結果としてzoom meeting id, calendar event id, status, updatedAtを記録。
6. 日程変更・キャンセルは双方へ同期し、失敗時はエラー表示と手動リトライを用意。会議の権限削除やリフレッシュトークン失効を検知し、過去の成功結果を新規成功として偽装しない。
7. テスト: 権限エラー、トークン失効、429制限、ネットワーク断、二重クリック、409競合、タイムゾーン、招待メールの扱い、部分成功リトライ、既存業務レコード保持。本人がGoogleカレンダーとZoomの両画面で実際に確認する。

## 外部統計の注意

- Jリーグ 2026特別シーズン・ドリブル総数:
  https://www.jleague.jp/j1/stats/player/2026/dribble_count/search-list/
- 海外 2025-26 U23成功ドリブル/90分:
  https://www.statmuse.com/fc/ask/successful-dribbles-per-90-leaders-in-europe-top-five-2026-u23
- **Jリーグのドリブル総数と海外の成功/90を同じ指標として比較しない。** 試行回数が少ない選手の成功率100%をそのまま最優先にするのも不可。出場分数・プレー映像・特徴・発信力・契約実現性を別軸で評価する。
- 候補を「提供済み」にするのは実際の提供契約が確認できた後だけ。ホームページの掲載には別途本人/クラブの承認が必要。

## デプロイ安全性

- Cloudflare Secrets、Cron、Workers設定、D1スキーマは今回PRで変更しない。
- 既存の `ss_documents` の任意フィールドを加えるだけ。バックアップの形式は維持し、古いレコードでも検証が成功する。
- 本番反映は別途PRレビュー・CI・事前バックアップ/復元検証・本番確認後。Codexレビューは保留の事実を残す。
